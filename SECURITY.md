# Security Policy

## Поддерживаемые версии

| Версия | Поддержка |
|--------|-----------|
| `v0.1.x` | ✅ Активная |
| `< v0.1` | ❌ Не поддерживается |

## Как сообщить об уязвимости

**НЕ создавай публичный issue** — это раскроет уязвимость до фикса.

### Способ 1: GitHub Security Advisories (рекомендуется)

1. Открой https://github.com/kwebhub/private-transfer/security/advisories
2. Нажми **"Report a vulnerability"**.
3. Заполни форму.

### Способ 2: Email

Отправь на `security@example.com` (TODO: заменить на реальный):

- **Тема:** `[SECURITY] zk-pool — <краткое описание>`
- **Тело:**
  - Описание уязвимости.
  - Шаги воспроизведения.
  - Влияние (что можно сломать).
  - Возможное решение (если есть).

### Что НЕ делать

- ❌ Не создавай **публичный issue**.
- ❌ Не публикуй в **Twitter/X**, **Discord**, **Telegram**.
- ❌ Не эксплуатируй уязвимость на **mainnet** (сейчас только devnet).
- ❌ Не атакуй **чужие депозиты** — только свои.

## Что мы обещаем

- **Ответ в течение 48 часов** (обычно быстрее).
- **Оценка серьёзности** в течение 5 дней.
- **Фикс** в течение 30 дней для критичных уязвимостей.
- **Публичное признание** (если хочешь) в `CHANGELOG.md` после фикса.

## Что считается уязвимостью

### Критичные

- **Double-spend:** вывод одного депозита дважды.
- **Подделка proof:** вывод без знания секретов.
- **Кража SOL из vault:** вывод на чужой адрес.
- **Обход verifier:** proof, проходящий без верификации.

### Средние

- **DoS:** вывод из строя backend / prover / merkle.
- **Утечка приватности:** deanonymization депозита.
- **Replay-атака:** повторное использование nullifier'а.
- **XSS:** кража deposit note из localStorage.

### Низкие

- **Утечка metadata:** IP-адреса, user-agent.
- **Rate limit bypass:** обход лимитов.
- **Утечка логов:** приватные данные в логах.

## Что НЕ считается уязвимостью

- ❌ **Trusted setup** — известное ограничение, не баг (см. [docs/threat-model.md](docs/threat-model.md#a10-toxic-waste-в-trusted-setup)).
- ❌ **Upgrade authority** — известное ограничение (см. [A11](docs/threat-model.md#a11-upgrade-программы)).
- ❌ **Backend видит commitments/nullifiers** — по дизайну.
- ❌ **localStorage** — известное ограничение (см. [A5](docs/threat-model.md#a5-перехват-deposit-note)).
- ❌ **Отсутствие HTTPS в devnet** — известное ограничение dev-среды.

## Security Best Practices для контрибьюторов

### Секреты

- ❌ **Никогда** не коммить:
  - `~/.config/solana/id.json` (Solana keypair).
  - `.env` (приватные ключи, пароли).
  - SSH-ключи.
- ✅ Используй `.env.example` как шаблон.
- ✅ Проверяй перед коммитом: `git diff --cached | grep -iE "secret|password|keypair|private"`.

### Зависимости

- **Dependabot** — автоматические PR на обновления (раз в неделю).
- **`cargo audit`** — проверка Rust-зависимостей.
- **`npm audit`** — проверка Node.js.
- **`trivy`** — проверка Docker-образов.

### Код

- **`cargo clippy -- -D warnings`** — обязателен.
- **Все `unsafe`** — с комментарием и обоснованием.
- **Все `unwrap()` / `expect()`** — только в тестах или там, где **невозможно** падение.
- **Все `pub` функции** — с doc-comments.

### Программа

- **Все PDA** — проверять `bump` через `ctx.bumps`.
- **Все `Signer`** — проверять явно.
- **Все CPI** — проверять `program_id`.
- **Все `require!`** — с понятным сообщением.

## Известные ограничения

Смотри [docs/threat-model.md](docs/threat-model.md) — там **полный** список.

**Кратко:**

1. **Trusted setup** — Sunspot использует стандартный setup без MPC.
2. **Upgrade authority** — один ключ, без мультисига.
3. **XSS** — deposit notes в localStorage.
4. **Backend видит commitments/nullifiers** — но не связь между ними.
